# 몽글몽글 구슬공방 — 물리 합성과 라운드 상태 관리

![몽글몽글 구슬공방 소개 이미지](../assets/thumbnails/marble-workshop.png)

같은 단계의 구슬을 떨어뜨려 합치고 주문한 단계까지 성장시키는 콘텐츠입니다. 구슬의 물리 충돌, 합성 처리, 목표 달성, 넘침 실패가 동시에 발생할 수 있어 입력과 물리 시뮬레이션의 상태를 함께 제어했습니다.

## 플레이 흐름

오프닝 → 조작 설명 → Seed부터 Tree까지 연습 → 목표 구슬 확인 → 낙하·합성 → 주문 완료 또는 넘침 실패 → 다음 라운드로 이어집니다. 상위 단계에서는 목표 구슬의 단계와 떨어지는 구슬 종류를 늘립니다. 조합표와 목표 미리보기를 통해 다음 목표를 확인할 수 있습니다.

## 구현: 충돌 한 쌍에서 합성은 한 번만

양쪽 구슬 모두 충돌 콜백을 받을 수 있으므로 인스턴스 ID로 처리 주체를 하나로 정합니다. 같은 단계인지, 낙하한 구슬인지, 이미 합성 중인지 검사한 뒤 양쪽의 합성 상태를 즉시 잠급니다. 물리 시뮬레이션을 멈추고 두 위치의 중간에 다음 단계 구슬을 생성한 후 기존 두 구슬을 제거합니다.

생성에 실패하면 잠금과 시뮬레이션을 복구합니다. 프리팹 목록의 순서를 실제 단계 값으로 초기화해 프리팹에 남은 과거 Inspector 값이 합성 규칙을 바꾸지 않도록 했습니다.

## 문제 해결: 넘침은 세션 종료가 아닌 라운드 실패

낙하 직후 구슬이 경계 위에 잠깐 놓이는 상황을 실패로 판정하지 않도록 초기 낙하 시간과 경계 위 체류 시간을 분리합니다. 경계 아래로 내려오면 체류 시간을 초기화하고, 유예 시간을 넘었을 때 실패를 제출합니다.

넘침 시 게임 전체를 종료하는 대신 해당 라운드의 실패를 기록하고 다음 라운드로 진행합니다. 최초 실패가 처리되면 입력과 물리가 잠기므로 여러 구슬이 같은 프레임에 넘쳐도 중복 제출을 차단합니다. 이 동작은 게임 전용 매니저에서 기존 공통 판정 흐름을 호출하는 방식으로 연결했습니다.

## 설명 중 물리 진행 방지

플레이 가능 여부에 준비 상태, 라운드 잠금, 튜토리얼 표시, 일시정지를 함께 반영합니다. 동일한 기준으로 드롭 입력과 Rigidbody2D 시뮬레이션을 제어해 설명 중 구슬만 움직이거나 합성이 일어나는 상태 불일치를 줄였습니다. 재시작과 오프닝 복귀에서는 코루틴, 미리보기와 보드 상태를 정리합니다.

## 낙하 구성 조절: 높은 단계 구슬의 연속 등장

마지막 구슬의 바로 전 단계가 연속 낙하하면 합성 과정이 짧아지는 문제가 있었습니다. 높은 단계 구슬을 완전히 제외하는 대신, 해당 구슬을 실제로 떨어뜨린 뒤 다음 두 번의 낙하에는 낮은 단계 구슬만 나오게 했습니다. 이후에는 기존 20% 선택 확률을 다시 적용합니다.

간격은 미리보기 생성 횟수가 아니라 실제 낙하 횟수로 계산합니다. 미리보기를 다시 만들거나 취소하는 동작이 간격을 소모하지 않도록 했고, 새 세션에서는 이력을 초기화합니다. 이 변경은 연속 등장만 줄이며, 큰 구슬이 쉽게 합쳐지는 모든 상황을 막는 정책은 아닙니다. 도달 난이도는 플레이 테스트로 추가 조정할 수 있습니다.

## 검토 기준

- 두 구슬의 동시 충돌 콜백이 다음 단계 구슬을 하나만 만드는지
- 낙하 직후 경계 접촉과 지속적인 넘침을 구분하는지
- 여러 구슬이 넘쳐도 실패가 한 번만 기록되는지
- 튜토리얼·일시정지·재시작에서 물리와 입력 상태가 일치하는지

이 문서는 구현을 설명하며 별도의 성능 측정 수치나 빌드 검증 결과를 주장하지 않습니다. 회사 원본 코드는 포함하지 않습니다.
