# 판다부동산 — 도면과 건물의 정답 일관성

<!-- 썸네일 업로드 후 활성화: ![판다부동산](../assets/panda-real-estate.png) -->

정면과 오른쪽에서 본 도면을 비교해 일치하는 건물을 고르는 공간 추론 콘텐츠입니다. 건물의 입체적인 인상과 실제 판정이 어긋나지 않도록, 문제 데이터와 보기의 가시성을 함께 다뤘습니다.

## 플레이와 난이도

오프닝 → 설명과 단계별 연습 → 도면 확인 → 건물 선택 → 피드백 → 다음 라운드로 진행합니다. Seed는 정면만 보여주고 오른쪽 방향표와 텍스트를 숨깁니다. Sprout부터 오른쪽 도면을 추가하며, Leaf·Tree에서는 높이와 보기 수를 늘립니다. 최종 구성에서는 창문 개수 조건, 위에서 본 도면, 상층의 별도 지붕 표현을 제거해 높이와 방향 비교에 집중했습니다.

## 구현: 하나의 높이 데이터에서 도면과 건물 생성

건물을 2×2 바닥의 네 기둥 높이로 표현했습니다. 정면은 같은 가로 위치에 놓인 기둥 높이의 최댓값, 오른쪽은 같은 깊이에 놓인 기둥 높이의 최댓값으로 계산합니다. 표시되는 도면과 정답 판정이 같은 높이 데이터를 사용하므로 화면과 판정의 기준을 일치시킬 수 있습니다.

Seed에서는 정면 투영만 비교하고, 이후 단계에서는 정면과 오른쪽 투영을 모두 비교합니다. Sprout 이상에는 정면이 같고 오른쪽이 다른 오답을 포함해 새로 추가된 도면을 실제로 확인해야 풀 수 있도록 구성했습니다.

## 문제 해결: 같은 보기와 가려진 기둥

단순히 높이 배열만 다르게 생성하면 회전하거나 대칭인 모양, 전체 크기만 다른 모양이 비슷한 보기로 나타날 수 있습니다. 회전·대칭·위치 이동과 높이 공약수 정규화를 적용한 대표 키로 중복 형태를 제외하고, 양쪽 투영이 모두 같은 후보도 중복 보기에서 제외했습니다. 오답 후보는 현재 단계의 정답 조건을 만족하지 않는 집에서 뽑습니다.

또한 앞 기둥에 가려 보이지 않는 뒷기둥이 정답을 결정하는 문제를 줄이기 위해, 후보 생성 단계에서 앞·뒤·양옆 기둥의 높이 관계를 제한했습니다. 전체 조합을 무작정 사용하는 대신 화면에서 판단할 수 있는 조합을 선택하는 방식입니다.

## 제작과 사용성

- 건물 몸체·문·창문 이미지와 방향표를 Inspector에서 설정합니다.
- 편집 모드의 보드 배치를 남겨 위치와 글자 크기를 조절할 수 있게 했습니다.
- 방향표의 높이를 맞추고 카드 경계를 기준으로 건물 표현을 조정했습니다.
- 튜토리얼은 설명과 하이라이트를 제공하고 스킵으로 본 게임에 진입합니다.

## 검토 기준

정답 조건을 만족하는 보기가 하나인지, 형태 키가 중복되지 않는지, Seed에서 오른쪽 UI가 숨겨지는지, 숨은 기둥이 판단을 좌우하지 않는지를 함께 확인해야 합니다. 데이터 검증만으로 Sprite의 투명 여백이나 실제 배치까지 보장되지는 않으므로 화면 검토가 별도로 필요합니다.

이 문서는 현재 구현의 구조와 개선 과정을 설명합니다. 썸네일은 콘텐츠 소개 이미지이며 플레이 검증 화면은 아닙니다. 회사 원본 코드와 내부 에셋은 포함하지 않습니다.
