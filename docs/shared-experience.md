# 여러 미니게임의 플레이 흐름과 결과 기록 정리

## 문제

게임별 제작 시기와 방식이 달라 튜토리얼 건너뛰기 버튼의 크기·문구·위치가 달랐고, 준비·시작 이미지와 dim의 표시 순서, 난이도 안내 유무도 달랐습니다. 화면 양식뿐 아니라 건너뛰기 후 손가락이나 튜토리얼 표시가 남는 상태도 함께 다뤄야 했습니다.

## 적용 방식

1. 오프닝에서 튜토리얼·준비·시작·본 게임으로 넘어가는 흐름을 확인했습니다.
2. 건너뛰기 버튼의 글자와 크기·위치를 맞추고, 게임별 안내에 해당 테마의 텍스트박스를 적용했습니다.
3. 난이도 상승 시 다음 단계의 실제 규칙을 설명하고 배지를 HUD로 연결했습니다.
4. 안내 코루틴, 손가락, dim, 입력 잠금과 진행 상태를 스킵·재시작·오프닝 복귀에서 정리했습니다.
5. 공통 스크립트를 수정할 필요가 없는 경우 게임 전용 연결과 연출 코드에서 처리했습니다.

모든 게임이 동일한 코드를 사용하는 것은 아닙니다. 기존 공통 게임 매니저와 UI를 활용하면서 각 게임의 이동·합성·회상·판정 규칙에 맞춰 연결했습니다. 일부 게임의 개별 안내 시간이나 진행 방식까지 동일하다고 주장하지 않습니다.

## 결과 로그와 고정 설정의 분리

시행 결과에는 문제 번호·난이도·정오답·반응시간과 게임별 문제 구성을 기록합니다. 예를 들어 모아이에서는 석상의 아이템 조합과 선택 항목, 패턴 게임에서는 문제 ID·선택지·재시도 순서를 남겨 결과를 해석할 수 있도록 했습니다.

고정 설정은 별도의 settings.json으로 관리합니다. 모아이의 오답 생성 규칙을 바꾸더라도 위치 교환 시간 설정은 같은 값일 수 있으며, 새 빌드는 식별 정보를 갱신해 구분합니다. 실제 서버 주소·식별자·내부 명세 데이터는 이 포트폴리오에 싣지 않습니다.

## 시간과 연출의 관계

남은 게임 시간, 문제 반응시간, 세션 경과시간은 목적이 다릅니다. 안내·추가 행동·결과 연출을 넣을 때 어느 기록에 포함되는지 확인해야 합니다. 화면의 타이머를 멈추는 것과 실제 경과시간을 제외하는 일을 같은 것으로 처리하지 않도록 구분했습니다.

## 검토 기준

- 건너뛰기 후 본 게임 배지와 입력 상태가 맞는가?
- 준비·시작 이미지가 dim에 가려지지 않는가?
- 다음 단계 안내가 실제 규칙과 일치하는가?
- 재시작 후 이전 안내·트윈·파티클이 남지 않는가?
- 정답·오답·재시도에서 결과가 중복되거나 빠지지 않는가?
