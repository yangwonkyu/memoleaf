# Fold Grid — 접힘 좌표와 점유 영역 판정

MemoLeaf 짐싸기 개발 경험의 핵심인 **접힌 상태의 좌표 변환과 겹침 판정**을 설명하기 위한 독립 Unity 예제입니다.

**이 예제는 기존 실무 경험을 검토한 뒤 Codex와 함께 새로 작성한 학습·설명용 코드입니다. 회사 제품 코드, 아트, 게임 데이터, 서비스 연동은 포함하지 않습니다. 이 샘플 자체를 당시 직접 작성한 실무 코드로 소개하지 않습니다.**

## 실행

검증에 사용한 버전: Unity 6000.3.10f1.

1. 저장소를 clone하거나 ZIP으로 다운로드한 뒤, Unity Hub에서 `samples/fold-grid` 폴더를 별도 프로젝트로 추가합니다.
2. `Assets/FoldGridDemo.unity`를 엽니다.
3. Play를 누릅니다.
4. 물건 크기를 고른 뒤 왼쪽 패널의 칸을 클릭합니다.
5. 왼쪽 위 체크를 해제하면 오른쪽 바닥 패널에 놓을 수 있습니다.
6. **Check folded layout**을 누르면 오른쪽에 접힌 점유 영역과 충돌 여부가 표시됩니다.
7. Undo / Reset으로 다른 배치를 비교합니다.

씬을 다시 만들려면 **Portfolio → Create Fold Grid Demo**를 사용합니다.

### 재현 예시

- 왼쪽 패널에 2×1 물건을 (0,0)에 놓습니다. 폭이 4이므로 접힌 시작 좌표는 (2,0)입니다.
- 오른쪽 패널 (2,0)에 1×1 물건을 놓고 검사하면 충돌입니다.
- Undo 후 오른쪽 (1,0)에 놓으면 경계만 맞닿고 겹치지 않습니다.
- 2×1 물건을 x=3에 배치하려 하면 패널 밖이므로 입력 단계에서 거절합니다.

## 설계

### 1. 표시와 판정 분리

`FoldRules.cs`는 Unity 타입에 의존하지 않습니다. 물건의 패널·좌표·폭·높이를 입력받아 판정하고, `FoldGridDemo.cs`는 입력과 표시를 담당합니다.

### 2. 물건 전체 영역을 반사

`foldedX = columns - openX - pieceWidth`

한 칸의 좌표만 반사하면 폭이 2 이상인 물건의 시작점이 잘못됩니다. 이 예제는 직사각형의 왼쪽 위 앵커를 반사된 전체 영역의 왼쪽 위 앵커로 변환합니다. 세로 좌표는 유지합니다.

### 3. 경계 접촉과 겹침 구분

축 정렬 직사각형의 반열린 범위를 비교합니다. 경계만 맞닿은 경우는 허용하고 실제 점유 칸이 겹칠 때만 충돌입니다. 판정 전에 크기와 경계 조건을 검증합니다.

### 4. 펼친 상태와 접힌 상태의 규칙 구분

같은 패널 위에서 겹치는 배치는 즉시 거절합니다. 서로 다른 패널의 물건은 배치할 수 있고, 접힘 검사에서 최종 충돌을 확인합니다.

## 검증

Unity 메뉴 **Portfolio → Validate Fold Rules**에서 반복 실행할 수 있습니다.

- 폭 1~6, 높이 1~4의 보드에서 가능한 모든 직사각형 위치·크기 검사
- 반사 후 경계 유지 및 두 번 반사하면 원래 위치로 돌아오는지 검사
- 직사각형 결과를 각 점유 칸의 개별 반사 결과와 비교
- 접힘 충돌, 경계 접촉, 영역 초과, 0 크기, 음수 위치, 빈 배치, 잘못된 보드 검사

실행 결과는 Console의 `FOLD_GRID_VALIDATION_PASSED` 로그에서 확인합니다.

2026-11-04, Unity 6000.3.10f1의 배치 실행에서 컴파일 성공 및 **4,767개 검증 조건 통과**를 확인했습니다. 이는 판정 로직에 대한 검증이며 UI 수동 조작 검증은 아직 하지 않았습니다.

자동 검증과 씬 생성을 함께 실행하려면 Unity 실행 파일에 아래 인수를 전달합니다.

```text
-batchmode -nographics -quit -projectPath "<이 샘플의 절대 경로>" -executeMethod ValidateFoldGrid.ValidateAndCreate -logFile "<검증 로그 경로>"
```

## 의도적으로 좁힌 범위

클릭 배치와 IMGUI를 사용한 기술 예제입니다. 제품 수준의 UI나 연출을 보여주는 자료는 기존 MemoLeaf 플레이 GIF를 참고합니다. 난이도 생성, 회전, 드래그, 애니메이션, 서버 통신은 이 샘플의 범위에 포함하지 않습니다.

충돌 검사는 물건 수 n에 대해 O(n²)입니다. 작은 보드의 설명용 코드에서는 명료함을 택했습니다. 물건이 많아지면 점유 셀 집합이나 공간 분할 방식과 비용을 비교할 수 있습니다.
